# SDK Architecture

This document describes the internal architecture of the DenseZK Rust SDK.

## Design Principles

The SDK implements a local proving pipeline. All cryptographic operations run in-process:

- **Witness generation** runs on-device using Poseidon hashing over the BN254 scalar field. Memory footprint is minimal.
- **Proving** runs locally using ark-groth16. A circuit-specific trusted setup is performed once, then proofs are generated and verified before being returned.

No network calls, no external servers.

## Dual-Target Compilation

The SDK compiles to two distinct targets from the same codebase:

| Target | Triple | Output | Consumer |
|---|---|---|---|
| Native | `x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`, etc. | `.rlib` / binary | Rust applications, CLI tools, servers |
| WASM | `wasm32-unknown-unknown` | `.wasm` + JS glue | React Native, web browsers |

The `wasm` module is gated behind `#[cfg(target_arch = "wasm32")]` and only compiles for the WASM target. All core logic (`client`, `prover`, `crypto`, `rel1cs`) is shared.

## Data Flow

### 1. Witness Generation (`DenseClient::create_witness`)

Input: `sender_id: u64`, `receiver_id: u64`, `weight: u64`

The client:
1. Constructs a `GraphEdge` from the three inputs
2. Feeds all three values as BN254 field elements into `PoseidonHasher::hash_edge`
3. Returns a `ClientWitness` containing the edge and the hex-encoded Poseidon commitment

The Poseidon hasher uses `Poseidon::<Fr>::new_circom(3)` which configures a 3-input sponge compatible with Circom's Poseidon gadget.

### 2. Local Proving (`LocalProver::setup` + `LocalProver::prove`)

**Setup** runs once:
1. Constructs a dummy `DenseZKCircuit` with zero-valued inputs
2. Calls `Groth16::<Bn254>::circuit_specific_setup` to generate the proving key and verifying key
3. Returns a `LocalProver` holding both keys

**Proving** runs per-proof:
1. Constructs a `DenseZKCircuit` from the witness and public inputs
2. The circuit defines witness variables for sender, receiver, weight and a public input for threshold
3. Enforces identity constraints (x * 1 = x) to bind the witness values into the R1CS
4. Calls `Groth16::<Bn254>::prove` to generate the proof
5. Verifies the proof internally using `Groth16::<Bn254>::verify_proof`
6. Serializes the proof to compressed bytes via `CanonicalSerialize::serialize_compressed`
7. Returns the `ZKProof`

### 3. High-Level Flow (`execute_dense_zk_flow`)

This convenience function chains witness generation and local proving together with logging. It is the recommended entry point for applications that do not need fine-grained control.

### 4. WASM Flow (`wasm.rs`)

The WASM module exposes three entry points to JavaScript:

- `init()` -- initializes the WASM module and sets up the panic hook
- `WasmClient.create_witness(sender, receiver, weight)` -- returns JSON string of `ClientWitness`
- `WasmProver.prove(witness_json, public_inputs_json)` -- returns JSON string of `ZKProof`
- `execute_flow(sender, receiver, weight, graph_root, threshold)` -- one-shot, returns JSON string of `ZKProof`

All values cross the WASM boundary as JSON strings or primitive types (`u64`, `&str`). The TypeScript wrapper in `react-native-sdk/` handles serialization and exposes idiomatic `Client` and `Prover` classes.

## Type Reference

### `DenseZKError`

| Variant | Trigger |
|---|---|
| `WitnessGenerationFailed` | Poseidon hashing or proof serialization failed |
| `SerializationError(serde_json::Error)` | JSON encode/decode fails |
| `ConstraintViolation` | R1CS constraint not satisfied or proof verification failed |
| `SetupFailed` | Groth16 circuit-specific setup failed |

### `GraphEdge`

Represents a directed edge in the social graph.

| Field | Type | Description |
|---|---|---|
| `sender_id` | `u64` | Source node identifier |
| `receiver_id` | `u64` | Target node identifier |
| `weight` | `u64` | Edge weight (e.g., interaction count) |

### `PublicInputs`

Public values that the verifier checks against.

| Field | Type | Description |
|---|---|---|
| `graph_root` | `String` | Merkle root of the current graph state |
| `threshold` | `u64` | Minimum follower count or predicate threshold |

### `ClientWitness`

The execution trace generated on-device. Serialized to JSON for transmission.

| Field | Type | Description |
|---|---|---|
| `edge` | `GraphEdge` | The social edge being proven |
| `commitment` | `String` | Hex-encoded Poseidon hash of the edge |

### `ZKProof`

The proof returned after local proving.

| Field | Type | Description |
|---|---|---|
| `proof_bytes` | `Vec<u8>` | Compressed Groth16 proof (128 bytes for BN254) |
| `root_commitment` | `String` | The graph root passed as public input |

### `LocalProver`

Holds the proving and verifying keys. Created via `LocalProver::setup()`.

## Cryptographic Primitives

### Poseidon Hash

The SDK uses `light-poseidon` with BN254 scalar field (`ark_bn254::Fr`). The hasher is configured with `new_circom(3)` for 3-input hashing, matching the Circom `Poseidon(3)` gadget used in the circuit suite.

Parameters:
- Curve: BN254
- S-box: x^5
- Width: 3 (rate=2, capacity=1)
- Full rounds: 8
- Partial rounds: 56 (for width=3)

### Groth16

- Curve: BN254 pairing-friendly elliptic curve
- Setup: Circuit-specific (randomized per prover instance)
- Proof size: 128 bytes (compressed canonical serialization)
- Verification: Performed internally before returning the proof

## Thread Safety

`DenseClient` is `!Sync` because `PoseidonHasher` maintains internal sponge state. `LocalProver` is `Sync` after setup and can be shared across threads for parallel proving.

## Error Handling

All SDK operations return `Result<T, DenseZKError>`. The error type implements `std::error::Error` and `Display` via `thiserror`. In WASM, errors are converted to `JsError` with the formatted error message.
